## 1. ภาพใหญ่: LLM คือฟังก์ชันที่มีปุ่มปรับได้

LLM รับข้อความเข้าไป แล้วตอบว่าคำถัดไปน่าจะเป็นคำอะไร ถ้ามองแบบโปรแกรมเมอร์ มันคือ method หนึ่งตัว

```java
static double[] predictNextToken(int[] tokens, double[] weights)
```

### `int[] tokens`: ข้อความที่แปลงเป็นหมายเลขแล้ว

โมเดลคำนวณได้แต่ตัวเลข จึงต้องตัดข้อความเป็นชิ้นเล็ก ๆ เรียกว่า **token**
แล้วแทนแต่ละชิ้นด้วยหมายเลขประจำตัวจากตารางคำศัพท์ (vocabulary)
ตารางนี้เทียบได้กับ `Map<String, Integer>` ที่กำหนดตายตัวไว้ล่วงหน้า

```
"แมว กิน ปลา"  →  ["แมว", " กิน", " ปลา"]  →  [1045, 233, 876]
```

เลขพวกนี้เป็น `int` เพราะเป็น **ID ไม่ใช่ปริมาณ** เหมือน primary key หรือ `ordinal()` ของ enum
ค่า 233 ไม่ได้ "น้อยกว่า" 876 ในความหมายใดเลย มันแค่ชี้ว่าเป็นช่องไหนในตาราง
(เลขในตัวอย่างสมมติขึ้น วิธีสร้างตารางนี้อยู่ในบทที่ 10)

### `double[] weights`: ตัวเลขที่ปรับได้

คือ "ปุ่มปรับ" ทั้งหมดของโมเดล เป็นอาร์เรย์ของจำนวนจริงจำนวนมาก (GPT-2 รุ่นเล็กมีราว 124 ล้านตัว)
ของจริงจัดเป็นเมทริกซ์หลายก้อน แต่โดยเนื้อแท้คือตัวเลขกองเดียว
เหตุที่เป็น `double` ไม่ใช่ `int` คือต้องขยับค่าทีละนิดได้ ซึ่งจะเห็นความสำคัญในหัวข้อ 6

### ค่าที่คืน `double[]`: ความน่าจะเป็นของ token ถัดไป

อาร์เรย์ที่คืนมายาวเท่ากับ**จำนวน token ทั้งหมดในตารางคำศัพท์** (GPT-2 มี 50,257 ช่อง)
ช่องที่ `i` คือความน่าจะเป็นที่ token ถัดไปจะเป็น ID `i` ทุกช่องรวมกันได้ 1

```
result[876]  = 0.62   // " ปลา"
result[4410] = 0.21   // " ข้าว"
result[91]   = 0.03   // " หนู"
...อีกราวห้าหมื่นช่อง ส่วนใหญ่ใกล้ศูนย์
```

### ทำไมคืนครบทุกช่อง ทั้งที่ส่วนใหญ่ใกล้ศูนย์

1. **ไม่รู้ล่วงหน้าว่าช่องไหนจะใกล้ศูนย์** การที่ช่องหนึ่งใกล้ศูนย์เป็น*ผลลัพธ์*ของการคำนวณ และเปลี่ยนไปทุกบริบท
   " ปลา" ได้ 0.62 หลัง "แมวกิน" แต่ใกล้ศูนย์หลัง "ฉันขับ"
2. **การเทรนต้องใช้ทุกช่อง** ความน่าจะเป็นรวมกันต้องได้ 1 การดันช่องที่ถูกให้สูงขึ้นจึงเท่ากับกดช่องอื่นทั้งหมดลง
   weight ที่เกี่ยวกับทุกช่องจึงได้รับการปรับ และตอนเริ่มเทรนที่ weight เป็นเลขสุ่ม
   ทุกช่องมีค่าพอ ๆ กันราว 1/50,257 ยังไม่มีช่องไหนใกล้ศูนย์ให้ตัดทิ้ง
3. **ต้นทุนต่ำเมื่อเทียบกับส่วนอื่น** ขั้นสุดท้ายของโมเดลคือการคูณเมทริกซ์ครั้งเดียวที่ให้คะแนนครบทุกช่องพร้อมกัน
   ซึ่งเป็นส่วนน้อยของงานคำนวณทั้งหมดต่อหนึ่ง token

การทิ้งช่องที่ไม่น่าใช้มีจริง แต่ทำ**หลังจาก**โมเดลคืนค่ามาแล้ว ในขั้นเลือก token (ดูหัวข้อย่อยถัดไป)

### ทำไมรับ `int[]` แต่ไม่คืน `int` ตัวเดียว

1. **ภาษามีคำตอบที่ถูกได้หลายแบบ** หลัง "แมวกิน" จะเป็น "ปลา" หรือ "ข้าว" ก็ได้
   การคืนความน่าจะเป็นบอกข้อมูลได้ครบกว่าการฟันธงคำเดียว
2. **ผลลัพธ์ต้องขยับทีละนิดได้** การเทรนทำงานโดยขยับ weight นิดหนึ่ง แล้วดูว่าผลลัพธ์เปลี่ยนไปนิดหนึ่งอย่างไร
   ความน่าจะเป็นขยับจาก 0.62 เป็น 0.63 ได้ แต่ token ID ขยับ "นิดหนึ่ง" ไม่ได้
   ถ้าผลลัพธ์เป็น `int` โมเดลจะไม่มีสัญญาณบอกว่าควรปรับไปทางไหน (หัวข้อ 3–6 จะอธิบายว่าทำไม)

### จากความน่าจะเป็นกลายเป็นข้อความ

โค้ดด้านนอกเป็นคนเลือก token จากความน่าจะเป็น แล้ววนเรียกซ้ำ

```java
while (!done) {
    double[] probs = predictNextToken(tokens, weights);
    int next = sample(probs);      // สุ่มเลือกตามน้ำหนักความน่าจะเป็น
    tokens = append(tokens, next); // ต่อท้าย แล้วถามใหม่
}
```

การที่ LLM "พิมพ์ทีละคำ" คือลูปนี้ และการที่ถามซ้ำแล้วได้คำตอบไม่เหมือนเดิมมาจากขั้น `sample`
(การแปลงผลลัพธ์ดิบให้เป็นความน่าจะเป็นอยู่ในบทที่ 5)

ขั้น `sample` คือจุดที่ทิ้งช่องที่ใกล้ศูนย์ มีสองวิธีที่นิยม

- **top-k** เก็บเฉพาะ k ช่องที่ค่าสูงสุด (เช่น 50 ช่อง) แล้วสุ่มจากกลุ่มนั้น
- **top-p** เก็บช่องที่ค่าสูงสุดไล่ลงมาจนผลรวมถึง p (เช่น 0.9) แล้วสุ่มจากกลุ่มนั้น

ทั้งสองวิธีกันไม่ให้สุ่มโดน token ที่ไม่เข้ากับบริบท ซึ่งแต่ละตัวมีโอกาสน้อยมาก
แต่รวมกันหลายหมื่นตัวแล้วมีโอกาสโดนไม่น้อย (รายละเอียดอยู่ในบทที่ 14)

### ลูปข้างบนคือ inference ส่วนการเทรนเป็นอีกลูปหนึ่ง

ลูป `while` ข้างบนคือการ**ใช้งาน**โมเดลที่เทรนเสร็จแล้ว เรียกว่า **inference**
สังเกตได้จากสองจุด: `weights` ไม่ถูกแก้ค่าเลย และมีการ `sample` เพื่อสร้างข้อความใหม่

ลูปการเทรนหน้าตาต่างออกไป

```java
for (Example ex : trainingData) {
    double[] probs = predictNextToken(ex.tokens, weights);
    double loss = howWrong(probs, ex.actualNextToken);  // วัดว่าผิดแค่ไหน
    double[] grads = derivativeOf(loss, weights);       // loss เปลี่ยนเท่าไรเมื่อขยับ weight แต่ละตัว
    for (int i = 0; i < weights.length; i++)
        weights[i] -= lr * grads[i];                    // ปรับ weight ให้ loss ลดลง
}
```

| | การเทรน | Inference |
|---|---|---|
| `weights` | ถูกปรับทุกรอบ | คงที่ |
| คำตอบที่ถูก | รู้อยู่แล้ว เพราะมาจากข้อความจริง | ไม่มี |
| `sample` | ไม่ใช้ | ใช้เลือก token ถัดไป |
| สิ่งที่ได้ | weights ที่ดีขึ้น | ข้อความใหม่ |

ตอนเทรนไม่ต้อง `sample` เพราะข้อมูลเทรนคือข้อความที่มีอยู่จริง เช่น "แมวกินปลา"
เราป้อน "แมวกิน" แล้วรู้อยู่แล้วว่าคำตอบคือ "ปลา" จึงแค่ดูว่าโมเดลให้ความน่าจะเป็นกับ "ปลา" เท่าไร

ทั้งสองลูปเรียก `predictNextToken` ตัวเดียวกัน ต่างกันที่สิ่งที่ทำกับผลลัพธ์
ตัวโค้ดของ method ไม่เปลี่ยนเลยตลอดการเทรน สิ่งที่เปลี่ยนคือค่าใน `weights` เท่านั้น
ตอนเริ่มต้นค่าเหล่านี้เป็นเลขสุ่ม โมเดลจึงตอบมั่ว

สองบรรทัดกลางของลูปการเทรน (`derivativeOf` และการปรับ weight) คือเนื้อหาของบทนี้ทั้งบท

**การเทรน คือการหาค่า `weights` ที่ทำให้โมเดลตอบผิดน้อยที่สุด**

ปัญหาจึงเหลือสองข้อ

1. วัด "ความผิด" ออกมาเป็นตัวเลขตัวเดียวได้อย่างไร ตัวเลขนี้เรียกว่า **loss**
2. ควรปรับ weight แต่ละตัวขึ้นหรือลง และปรับเท่าไร เพื่อให้ loss ลดลง

บทนี้ตอบข้อ 2 ในกรณีที่ง่ายที่สุด คือมี weight ตัวเดียว บทถัดไปจะขยายเป็นหลายตัว

## 2. ฟังก์ชัน

ฟังก์ชันทางคณิตศาสตร์คือ method ที่รับตัวเลขเข้า คืนตัวเลขออก และไม่มี side effect
ใส่ค่าเดิมเข้าไปกี่ครั้งก็ได้ค่าเดิมออกมา

คณิตศาสตร์เขียนว่า $f(x) = x^2$ ซึ่งตรงกับโค้ด

```python
def f(x):
    return x * x
```

$f(3)$ อ่านว่า "เอฟของสาม" หมายถึงเรียก `f(3)` ซึ่งได้ 9

ถ้าลองแทนค่าหลายค่าแล้วเขียนเป็นตาราง

| $x$ | −3 | −2 | −1 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|---|---|---|
| $f(x) = x^2$ | 9 | 4 | 1 | 0 | 1 | 4 | 9 |

เมื่อนำไปพล็อตกราฟจะได้รูปชาม จุดก้นชามอยู่ที่ $x = 0$

ให้มองว่า $x$ คือ weight และ $f(x)$ คือ loss
**งานของเราคือหา $x$ ที่อยู่ก้นชาม** ในตัวอย่างนี้มองตารางก็รู้คำตอบ
แต่ฟังก์ชัน loss ของ LLM ซับซ้อนเกินกว่าจะพล็อตดูได้ จึงต้องมีวิธีที่เป็นระบบ

## 3. ความชัน: ถ้าขยับ x นิดหนึ่ง ผลลัพธ์เปลี่ยนเท่าไร

สมมติเรายืนอยู่บนกราฟที่ $x = 3$ โดยมองไม่เห็นรูปร่างกราฟทั้งหมด
วิธีเดียวที่จะรู้ว่าควรเดินไปทางไหนคือ **ลองขยับดูนิดหนึ่ง แล้วดูว่าค่าเปลี่ยนอย่างไร**

ขยับจาก $x = 3$ ไป $x = 4$ (ขยับ 1 หน่วย)

- ค่าเดิม $f(3) = 9$
- ค่าใหม่ $f(4) = 16$
- ค่าเพิ่มขึ้น $16 - 9 = 7$

อัตราการเปลี่ยนแปลงคือ "ผลลัพธ์เปลี่ยนไปเท่าไร ต่อการขยับ 1 หน่วย" เรียกว่า **ความชัน (slope)**

$$\text{ความชัน} = \frac{\text{ผลลัพธ์เปลี่ยนไปเท่าไร}}{\text{ขยับ x ไปเท่าไร}} = \frac{f(x+h) - f(x)}{h}$$

โดย $h$ คือระยะที่ขยับ ในตัวอย่างข้างบน $h = 1$ จึงได้ความชัน $7 / 1 = 7$

ความชันบอกสองอย่าง

- **เครื่องหมาย** บอกทิศ ถ้าเป็นบวกแปลว่าเพิ่ม $x$ แล้วค่าเพิ่ม ถ้าเป็นลบแปลว่าเพิ่ม $x$ แล้วค่าลด
- **ขนาด** บอกความไว ความชัน 7 แปลว่าขยับ $x$ นิดเดียว ผลลัพธ์เปลี่ยนมากกว่านั้นราว 7 เท่า

เขียนเป็นโค้ดได้ตรงตัว

```python
def slope(f, x, h):
    return (f(x + h) - f(x)) / h
```

`f` ถูกส่งเป็นพารามิเตอร์ เหมือนส่ง `DoubleUnaryOperator` ใน Java

### ปัญหา: ค่าที่ได้ขึ้นกับ h

ความชัน 7 เป็นค่า**เฉลี่ย**ตลอดช่วง 3 ถึง 4 แต่กราฟโค้ง ความชันจึงไม่เท่ากันตลอดช่วง
เราอยากรู้ความชัน **ที่จุด $x = 3$ พอดี** จึงลองลด $h$ ลงเรื่อย ๆ

```
h = 1       ความชัน = 7.000000
h = 0.1     ความชัน = 6.100000
h = 0.01    ความชัน = 6.010000
h = 0.001   ความชัน = 6.001000
h = 0.0001  ความชัน = 6.000100
```

ยิ่ง $h$ เล็ก ค่ายิ่งเข้าใกล้ 6 ค่าที่มันเข้าใกล้นี้คือสิ่งที่เราต้องการ

## 4. อนุพันธ์: ความชัน ณ จุดเดียว

**อนุพันธ์ (derivative)** ของ $f$ ที่จุด $x$ คือค่าที่ความชันเข้าใกล้ เมื่อ $h$ เล็กลงจนเกือบเป็นศูนย์

$$f'(x) = \lim_{h \to 0} \frac{f(x+h) - f(x)}{h}$$

อ่านสัญลักษณ์ทีละตัว

- $f'(x)$ อ่านว่า "เอฟไพรม์ของเอ็กซ์" คืออนุพันธ์ของ $f$ ที่จุด $x$
- $\lim_{h \to 0}$ อ่านว่า "ลิมิตเมื่อ $h$ เข้าใกล้ศูนย์" คือค่าที่นิพจน์ทางขวาเข้าใกล้ เมื่อ $h$ เล็กลงเรื่อย ๆ

### ทำไมไม่แทน h = 0 ไปเลย

เพราะจะได้ $\frac{f(x) - f(x)}{0} = \frac{0}{0}$ ซึ่งไม่มีความหมาย
วิธีที่ถูกคือ **จัดรูปให้ $h$ ที่เป็นตัวหารหายไปก่อน** แล้วค่อยดูว่าเหลืออะไรเมื่อ $h$ เล็กมาก

### คำนวณด้วยมือ: อนุพันธ์ของ $x^2$

เริ่มจากนิยาม แทน $f(x) = x^2$

$$\frac{(x+h)^2 - x^2}{h}$$

กระจาย $(x+h)^2 = (x+h)(x+h) = x^2 + 2xh + h^2$

$$= \frac{x^2 + 2xh + h^2 - x^2}{h}$$

$x^2$ กับ $-x^2$ ตัดกัน

$$= \frac{2xh + h^2}{h}$$

ทุกพจน์ด้านบนมี $h$ จึงหารด้วย $h$ ได้

$$= 2x + h$$

ตอนนี้ไม่มี $h$ เป็นตัวหารแล้ว เมื่อ $h$ เล็กลงจนเกือบศูนย์ พจน์ $+h$ ก็หายไป เหลือ

$$f'(x) = 2x$$

ตรวจกับผลที่รันไว้: ที่ $x = 3$ ได้ $2 \times 3 = 6$ ตรงกัน
และสังเกตว่าตารางข้างบนให้ค่า $6 + h$ ทุกบรรทัด (7, 6.1, 6.01, ...) ตรงกับ $2x + h$ ที่เพิ่งคำนวณได้

**ข้อสังเกตสำคัญ:** อนุพันธ์เป็นฟังก์ชันตัวใหม่ ไม่ใช่ตัวเลขตัวเดียว
ป้อน $x$ เข้าไป มันบอกความชันของ $f$ ที่จุดนั้น

| $x$ | −3 | −1 | 0 | 1 | 3 |
|---|---|---|---|---|---|
| $f'(x) = 2x$ | −6 | −2 | 0 | 2 | 6 |

ทางซ้ายของก้นชามความชันเป็นลบ ทางขวาเป็นบวก และ**ที่ก้นชามความชันเป็นศูนย์** เพราะพื้นตรงนั้นราบ

### ที่มา

- **ปัญหาตั้งต้น** มีสองข้อที่นักคณิตศาสตร์ศตวรรษที่ 17 อยากแก้ ข้อแรกคือความเร็ว ณ ขณะใดขณะหนึ่ง
  (ความเร็วคือระยะทางหารเวลา แต่ "ณ ขณะหนึ่ง" เวลาเป็นศูนย์) ข้อสองคือเส้นสัมผัสของเส้นโค้ง
  ทั้งสองเป็นปัญหาเดียวกับที่เราเพิ่งเจอ คือหาความชันเมื่อช่วงเล็กจนเป็นศูนย์
- **Isaac Newton** (อังกฤษ ราวปี 1665–1666) และ **Gottfried Wilhelm Leibniz** (เยอรมนี ตีพิมพ์ปี 1684)
  ต่างคนต่างคิดวิธีนี้ขึ้นมาโดยไม่ขึ้นต่อกัน สัญลักษณ์ $\frac{dy}{dx}$ ที่ใช้กันทุกวันนี้เป็นของ Leibniz
- **จุดอ่อน** ทั้งคู่ใช้ "ปริมาณที่เล็กมากจนเกือบเป็นศูนย์" ซึ่งบางบรรทัดถือว่าไม่เป็นศูนย์ (เพื่อให้หารได้)
  แต่บรรทัดต่อมากลับทิ้งไปเหมือนเป็นศูนย์ ปี 1734 บิชอป George Berkeley วิจารณ์เรื่องนี้ว่าเป็น
  "ผีของปริมาณที่ล่วงลับไปแล้ว"
- **ทางแก้** มาในศตวรรษที่ 19 เมื่อ Augustin-Louis Cauchy และ Karl Weierstrass นิยาม**ลิมิต**อย่างรัดกุม
  โดยไม่ต้องพูดถึงปริมาณที่เล็กไม่สิ้นสุดเลย พูดแค่ว่า "ทำให้ผลลัพธ์ใกล้ค่าเป้าหมายเท่าไรก็ได้ ด้วยการเลือก $h$ ให้เล็กพอ"

### สัญลักษณ์สองแบบ

ทั้งสองแบบหมายถึงสิ่งเดียวกัน บทต่อ ๆ ไปจะใช้ทั้งคู่

| แบบ | เขียน | อ่านว่า | เจ้าของ |
|---|---|---|---|
| ไพรม์ | $f'(x)$ | เอฟไพรม์ของเอ็กซ์ | Lagrange |
| เศษส่วน | $\frac{df}{dx}$ หรือ $\frac{dy}{dx}$ | ดีเอฟ บาย ดีเอ็กซ์ | Leibniz |

แบบ Leibniz ชวนให้นึกถึง "ผลลัพธ์เปลี่ยนเท่าไร หารด้วย $x$ เปลี่ยนเท่าไร" ซึ่งตรงกับความหมายของความชัน

## 5. กฎการหาอนุพันธ์

การกระจายจากนิยามทุกครั้งเสียเวลา จึงมีกฎสำเร็จรูป ทุกกฎได้มาจากการทำแบบหัวข้อ 4 หนึ่งครั้งแล้วจำผลไว้

| กฎ | ฟังก์ชัน | อนุพันธ์ | เหตุผลสั้น ๆ |
|---|---|---|---|
| ค่าคงที่ | $c$ | $0$ | ค่าไม่เปลี่ยนเลย ความชันจึงเป็นศูนย์ |
| เส้นตรง | $x$ | $1$ | ขยับ $x$ เท่าไร ผลลัพธ์เปลี่ยนเท่านั้นพอดี |
| ยกกำลัง | $x^n$ | $n \cdot x^{n-1}$ | เอาเลขชี้กำลังลงมาคูณ แล้วลดเลขชี้กำลังลงหนึ่ง |
| คูณค่าคงที่ | $c \cdot f(x)$ | $c \cdot f'(x)$ | ขยายกราฟแนวตั้ง $c$ เท่า ความชันก็ขยาย $c$ เท่า |
| ผลบวก | $f(x) + g(x)$ | $f'(x) + g'(x)$ | การเปลี่ยนแปลงของแต่ละส่วนบวกกันได้ตรง ๆ |

**ตัวอย่าง:** หาอนุพันธ์ของ $f(x) = x^2 - 6x + 9$

ใช้กฎผลบวกแยกทีละพจน์

- $x^2$ ใช้กฎยกกำลัง ได้ $2x^1 = 2x$
- $-6x$ ใช้กฎคูณค่าคงที่กับกฎเส้นตรง ได้ $-6 \times 1 = -6$
- $9$ ใช้กฎค่าคงที่ ได้ $0$

รวมกันได้ $f'(x) = 2x - 6$

### ทำไมกฎยกกำลังถึงเป็นแบบนั้น

ดูจากกรณี $x^2$ ที่ทำไว้: เมื่อกระจาย $(x+h)^2$ จะได้ $x^2 + 2xh + h^2$

- พจน์ $x^2$ ตัดกับ $-x^2$ เสมอ
- พจน์ที่มี $h$ ตัวเดียว ($2xh$) หารด้วย $h$ แล้วเหลือ $2x$ นี่คือคำตอบ
- พจน์ที่มี $h$ ตั้งแต่สองตัวขึ้นไป ($h^2$) หารแล้วยังเหลือ $h$ ติดอยู่ จึงหายไปเมื่อ $h$ เข้าใกล้ศูนย์

กรณี $x^n$ ทั่วไปก็เป็นเช่นเดียวกัน เมื่อกระจาย $(x+h)^n$ พจน์ที่มี $h$ ตัวเดียวคือ $n \cdot x^{n-1} \cdot h$ เสมอ
(มี $n$ วิธีในการเลือกว่าวงเล็บไหนจะส่ง $h$ ออกมา ส่วนวงเล็บที่เหลืออีก $n-1$ วงส่ง $x$)
แบบฝึกหัดข้อ 4 จะให้คุณลองทำเองกับ $x^3$

ตรวจด้วยโค้ดได้เสมอ ผลจาก `slope.py`

```
x = -2  วัดด้วยโค้ด =    12.0000   สูตร 3x^2 = 12
x =  0  วัดด้วยโค้ด =     0.0000   สูตร 3x^2 = 0
x =  1  วัดด้วยโค้ด =     3.0000   สูตร 3x^2 = 3
x =  5  วัดด้วยโค้ด =    75.0000   สูตร 3x^2 = 75
```

### ข้อควรระวังเมื่อใช้โค้ดวัดความชัน

ถ้า $h$ เล็กเกินไป ผลจะผิด เพราะ `double` เก็บเลขนัยสำคัญได้ราว 16 หลัก

```
h = 1e-08   ความชัน = 5.999999963535174
h = 1e-12   ความชัน = 6.000533403494046
h = 1e-16   ความชัน = 0.0
h = 1e-20   ความชัน = 0.0
```

ที่ $h = 10^{-16}$ คอมพิวเตอร์มองว่า $3 + h$ เท่ากับ $3$ ตัวเศษจึงเป็นศูนย์
นี่เป็นเหตุผลหนึ่งที่ของจริงไม่ใช้วิธีวัดแบบนี้ แต่ใช้สูตรอนุพันธ์ที่คำนวณได้แม่นยำ
(อีกเหตุผลคือความเร็ว ซึ่งจะเห็นชัดในบทที่ 3)

## 6. Gradient descent: เดินลงเนินด้วยอนุพันธ์

ตอนนี้เรามีเครื่องมือบอกความชัน ณ จุดที่ยืนอยู่ วิธีหาก้นชามจึงตรงไปตรงมา

1. ดูความชันที่จุดปัจจุบัน
2. เดินไปทาง**ตรงข้าม**กับความชัน
3. ทำซ้ำ

$$x_{\text{ใหม่}} = x_{\text{เดิม}} - \eta \cdot f'(x_{\text{เดิม}})$$

$\eta$ (อักษรกรีก อ่านว่า "อีตา") คือ **learning rate** หรือขนาดก้าว เป็นเลขบวกค่าเล็ก ๆ ที่เราเลือกเอง

### ทำไมต้องเป็นเครื่องหมายลบ

- ความชันเป็น**บวก** แปลว่าเพิ่ม $x$ แล้วค่าเพิ่ม เราอยากให้ค่าลด จึงต้อง**ลด** $x$
- ความชันเป็น**ลบ** แปลว่าเพิ่ม $x$ แล้วค่าลด จึงต้อง**เพิ่ม** $x$

ทั้งสองกรณีคือขยับสวนทางกับเครื่องหมายของความชัน การลบ $f'(x)$ ออกทำแบบนั้นให้โดยอัตโนมัติ

### ทำไมคูณด้วยความชัน ไม่ใช่ก้าวเท่ากันทุกครั้ง

ใกล้ก้นชามพื้นจะราบ ความชันจึงเล็ก ก้าวก็เล็กตาม ทำให้ชะลอเองเมื่อใกล้ถึง และหยุดเมื่อความชันเป็นศูนย์

### โค้ด

```python
def gradient_descent(df, x, lr, steps):
    path = [x]
    for _ in range(steps):
        x = x - lr * df(x)
        path.append(x)
    return path
```

ลองกับ $f(x) = (x-3)^2 = x^2 - 6x + 9$ ซึ่งมีก้นชามที่ $x = 3$ และ $f'(x) = 2x - 6$ (คำนวณไว้ในหัวข้อ 5)
เริ่มที่ $x = 0$ ใช้ $\eta = 0.1$

คำนวณก้าวแรกด้วยมือ

- ความชันที่ $x = 0$ คือ $2(0) - 6 = -6$
- $x_{\text{ใหม่}} = 0 - 0.1 \times (-6) = 0.6$

ผลจากโค้ด

```
ก้าวที่  0: x = 0.00000   f(x) = 9.00000
ก้าวที่  1: x = 0.60000   f(x) = 5.76000
ก้าวที่  2: x = 1.08000   f(x) = 3.68640
ก้าวที่  3: x = 1.46400   f(x) = 2.35930
ก้าวที่  5: x = 2.01696   f(x) = 0.96637
ก้าวที่ 10: x = 2.67788   f(x) = 0.10376
ก้าวที่ 20: x = 2.96541   f(x) = 0.00120
ก้าวที่ 30: x = 2.99629   f(x) = 0.00001
```

$x$ เข้าใกล้ 3 และก้าวสั้นลงเรื่อย ๆ ตามที่คาดไว้

### ที่มา

Augustin-Louis Cauchy (คนเดียวกับที่นิยามลิมิต) เสนอวิธีนี้ในปี 1847 เพื่อแก้ระบบสมการในการคำนวณวงโคจรของดาว
เกือบ 180 ปีต่อมา วิธีเดียวกันนี้ (พร้อมการปรับปรุงเล็กน้อย) ยังเป็นวิธีหลักที่ใช้เทรน LLM ทุกตัว

## 7. โมเดลตัวแรก: เรียนรู้จากข้อมูล

นำทุกอย่างมาต่อกัน สร้างโมเดลที่เล็กที่สุดเท่าที่เป็นไปได้ มี weight ตัวเดียว

$$\text{ทำนาย} = w \cdot x$$

มีข้อมูลตัวอย่างหนึ่งคู่: เมื่อ $x = 2$ คำตอบที่ถูกคือ $y = 10$ โมเดลต้องหาเองว่า $w$ ควรเป็นเท่าไร

**ขั้นที่ 1: นิยาม loss** ใช้ผลต่างระหว่างค่าทำนายกับคำตอบ แล้วยกกำลังสอง

$$\text{loss}(w) = (2w - 10)^2$$

เหตุผลที่ยกกำลังสอง

- ผลลัพธ์ไม่ติดลบ การทำนายเกินหรือขาดถือว่าผิดทั้งคู่
- ผิดมากโดนลงโทษหนักกว่าผิดน้อยแบบทวีคูณ
- กราฟเป็นรูปชามเรียบ มีก้นเดียว หาอนุพันธ์ได้ทุกจุด

สังเกตว่า loss เป็นฟังก์ชันของ $w$ ไม่ใช่ของ $x$ เพราะข้อมูลถูกกำหนดตายตัวแล้ว สิ่งที่เราปรับได้คือ $w$

**ขั้นที่ 2: หาอนุพันธ์** กระจายก่อน

$$(2w - 10)^2 = 4w^2 - 40w + 100$$

ใช้กฎจากหัวข้อ 5

$$\frac{d\,\text{loss}}{dw} = 8w - 40$$

**ขั้นที่ 3: gradient descent** เริ่มที่ $w = 0$ ใช้ $\eta = 0.05$

```
ก้าวที่  0: w = 0.00000   ทำนาย y = 0.00000   loss = 100.00000
ก้าวที่  1: w = 2.00000   ทำนาย y = 4.00000   loss = 36.00000
ก้าวที่  2: w = 3.20000   ทำนาย y = 6.40000   loss = 12.96000
ก้าวที่  3: w = 3.92000   ทำนาย y = 7.84000   loss = 4.66560
ก้าวที่  5: w = 4.61120   ทำนาย y = 9.22240   loss = 0.60466
ก้าวที่ 10: w = 4.96977   ทำนาย y = 9.93953   loss = 0.00366
ก้าวที่ 20: w = 4.99982   ทำนาย y = 9.99963   loss = 0.00000
```

โมเดลพบเองว่า $w = 5$ โดยที่เราไม่ได้บอกคำตอบ เราบอกเพียงว่า "ผิดแค่ไหน" และ "ผิดไปทางไหน"

**นี่คือการเทรนโมเดลทั้งหมด** GPT ทำสิ่งเดียวกันนี้ ต่างกันที่ขนาด

| | โมเดลของเรา | GPT |
|---|---|---|
| จำนวน weight | 1 | หลายร้อยล้านถึงหลายแสนล้าน |
| ฟังก์ชัน | $w \cdot x$ | Transformer (บทที่ 11–13) |
| loss | ผลต่างยกกำลังสอง | cross-entropy (บทที่ 5) |
| วิธีหาอนุพันธ์ | กระจายด้วยมือ | backpropagation (บทที่ 3) |
| วิธีปรับ weight | gradient descent | gradient descent (รุ่นปรับปรุง) |

---

## สรุป

- LLM คือฟังก์ชันที่มี weight จำนวนมาก การเทรนคือการหา weight ที่ทำให้ loss ต่ำที่สุด
- **ความชัน** $\frac{f(x+h) - f(x)}{h}$ บอกว่าผลลัพธ์เปลี่ยนเท่าไรเมื่อขยับ $x$
- **อนุพันธ์** $f'(x)$ คือความชัน ณ จุดเดียว ได้จากการให้ $h$ เข้าใกล้ศูนย์
- กฎยกกำลัง: อนุพันธ์ของ $x^n$ คือ $n \cdot x^{n-1}$
- **Gradient descent:** $x \leftarrow x - \eta \cdot f'(x)$ ทำซ้ำจนถึงจุดที่ความชันเป็นศูนย์

## สิ่งที่ยังค้าง และบทถัดไปจะตอบ

1. ในหัวข้อ 7 เรากระจาย $(2w-10)^2$ ก่อนหาอนุพันธ์ ถ้าสูตรซ้อนกันเป็นร้อยชั้นจะกระจายไม่ไหว
   ต้องใช้ **chain rule** (บทที่ 3)
2. โมเดลจริงมี weight หลายตัว ต้องรู้ความชันของ loss เทียบกับ weight **แต่ละตัว**
   เรียกว่า **partial derivative** และ **gradient** (บทที่ 2)
